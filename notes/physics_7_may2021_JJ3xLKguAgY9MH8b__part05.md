**Paragraph 1 (Definition + measurement setup):**
- **S1** — *Claim/definition*: "The dependent variable is the range." → Hands off because the reader needs to know *how* it is measured; the next sentence supplies the apparatus.
- **S2** — *Procedure setup (apparatus placement)*: "A measuring tape was put on the incline plank and a phone was set up on a tripod" → Hands off by leaving the *source* of the measurement ambiguous; the next sentence tells the reader the tape is not read in real time.
- **S3** — *Source/evidence handling + forward signpost*: "The range was recorded later from the videos" → Hands off by closing this measurement story but flagging processing elsewhere; the next paragraph shifts from *how* it was measured to *the limit* on how big it can be.

**Paragraph 2 (Authority + setup justification):**

## What This Section Does (content sequence)

A "Dependent variable" section in IB Physics IA typically performs, in order:

1. **Name the variable** — anchors the reader to what is being measured.
2. **State the measuring instrument and where it sits** — the apparatus needs a known geometry before any number is trusted.
3. **State the data-capture medium** (video, logger, scale) — bridges to how raw numbers are extracted.
4. **Signpost later processing** — keeps the section from bloating into Section 4.
5. **Cite an external limit / authority** — introduces a real-world constraint that bounds the experiment.
6. **Apply that limit to the chosen setup** — turns the citation into a design choice (not just a number quoted).
7. **State repeats per condition with the reason** — addresses random error, the only error class repeats can fight.
8. **Compute the total sample size** — closes with a concrete scale figure.

Order matters: you must define *what* you measure (1) before justifying *how well* (5–8); you must cite the limit (5) before applying it (6); you must state the per-condition repeat count (7) before the total (8) because the total is mechanically derived.

## Paragraph Skeletons (replicable templates)

**Skeleton A — "Definition + measurement rig"**
- `SKELETON: "The dependent variable is the [quantity]. [Instrument A] was [placed where] and [Instrument B] was [set up how] to [capture what]. The [quantity] was recorded [source/timing] ([forward signpost])."`
- **Slots:**
  1. *Quantity* (noun phrase).
  2. *Placement verb + location* (past simple).
  3. *Second instrument + capture method* (past simple + infinitive of purpose).
  4. *Source phrase + parenthetical cross-reference to processing section*.
- **How to fill with a new idea:** Slot 1 = name a measurable outcome of your experiment. Slot 2 = pick a ruler/sensor and a fixed surface. Slot 3 = pick a recorder (camera, datalogger, stopwatch). Slot 4 = name the medium you read numbers from and bracket the cross-reference.
- **Original fill:** "The dependent variable is the range. A measuring tape was put on the incline plank and a phone was set up on a tripod to slow-motion record the projectile falling on the plank. The range was recorded later from the videos (Data processing showed more in Section 4)."
- **Demo fill (different subject):** "The dependent variable is the half-life. A Geiger-Müller tube was placed 5 cm from the source and a video was set up to slow-motion record the counter ticking over. The half-life was recorded later from the counter readings (Data processing is shown in Section 4)."

**Skeleton B — "Authority quote + constraint-based setup"**
- `SKELETON: "The [equipment] gives [capability] '[quoted figure]' (citation). The [equipment] was set up so that [primary constraint] but also [secondary constraint] so that [optimisation goal]."`
- **Slots:**
  1. *Equipment name + manufacturer claim + verbatim figure in quotes + bracketed citation*.
  2. *Primary constraint* (not exceeding limit).
  3. *Secondary constraint / floor* (minimum measurable value).
  4. *Optimisation goal* (small fractional uncertainty, large signal, etc.).
- **How to fill:** Slot 1 = find a datasheet number that bounds your variable. Slot 2 = restate that bound. Slot 3 = restate your own floor requirement. Slot 4 = name the error metric you are shrinking.
- **Original fill:** "The Vernier Projectile Launcher gives repeatability 'up to a distance of 2.5 m' (2: p.3). The Launcher was set up so that the range would not go over this limit but also be over 2 meters at α = 0 so that the fractional uncertainties in the range would be as small as possible."
- **Demo fill (different subject):** "The Pasco Rotary Motion Sensor gives resolution 'down to 0.05°' (3: p.2). The sensor was set up so that the angular displacement would not exceed this resolution but also be over 30° per trial so that the fractional uncertainty in period would be as small as possible."

**Skeleton C — "Repeats with reason + total"**
- `SKELETON: "The experiment was repeated [N] times for every [independent variable level] to reduce effects from [error class]. This means there were total of [N × levels] data points."`
- **Slots:**
  1. *Repeat count* (small integer).
  2. *Stratification variable* (every angle / every mass / every temperature).
  3. *Error class* (random uncertainties / human reaction-time spread).
  4. *Derived total* (product).
- **How to fill:** N must be small enough to be feasible but >3. The error class must be one that repetition actually fights (random, not systematic).
- **Original fill:** "The experiment was repeated 8 times for every incline angle to reduce effects from random uncertainties. This means there were total of 112 data points."
- **Demo fill:** "The experiment was repeated 5 times for every mass on the spring to reduce effects from random uncertainties in the oscillation period. This means there were total of 35 data points."

## Express-Idea Vocabulary

- **Sequencing / order:** "later" — *"The range was recorded **later** from the videos"*; "also" — *"**but also** be over 2 meters"*.
- **Cause / purpose (the dominant connector):** "so that" — *"set up **so that** the range would not go over this limit"*; *"**so that** the fractional uncertainties … would be as small as possible"*; "to" (infinitive of purpose) — *"set up on a tripod **to** slow-motion record"*.
- **Contrast / additive constraint:** "but also" — *"would not go over this limit **but also** be over 2 meters"*.
- **Evidence handling:** bracketed citation *"up to a distance of 2.5 m" (2: p.3)*; parenthetical forward-pointer *"(Data processing showed more in Section 4)"*.
- **Definition verbs:** "is the" — *"The dependent variable **is the** range"*; "gives" — *"The Vernier Projectile Launcher **gives** repeatability"*.
- **Specification / optimisation:** "as small as possible" — *"fractional uncertainties in the range would be **as small as possible"*.
- **Aggregation / consequence:** "This means" — *"**This means** there were total of 112 data points"*.

## How to Explain an Idea (replication steps)

The pattern is **authority quote → two-sided constraint → quantification of error**. To explain a *new* "Dependent variable" idea:

1. **Define** the variable in one noun phrase ("The dependent variable is X").
2. **Describe the rig** — one passive placement + one purpose-clause for the recorder.
3. **Locate the data source** in time and signpost later processing in parentheses.
4. **Quote a manufacturer/spec limit** with a verbatim figure and a bracketed citation.
5. **Translate that figure into a setup rule** using "set up so that [upper bound] but also [lower bound]".
6. **Attach an optimisation goal** after a second "so that" — name the error metric being minimised.
7. **State the repeat count per condition** with the error class it fights.
8. **Compute the total** in one short consequence sentence using "This means".

The rhythm is: *one-line definition → three-line rig → two-line authority → one-line repeat → one-line total*. Any new IA section of this type should hit those eight moves in that order.
