## Paragraph Flow (move by move)

**Paragraph 1**

1. **Sentence 1** — *Context/requirement statement*: "The problem requires the cube's edges to be twice the length" — establishes the numerical demand the rest of the section must answer. Hands forward by *consequence* (the demand forces a specific tool).
2. **Sentence 2** — *Consequence + transition to display*: "therefore the scale matrix looks as follows:" — the connector "therefore" delivers the consequence of sentence 1 and points the reader at the matrix that follows. Hands forward by *specification* (here is the tool).
3. **[Matrix S]** — *Tool evidence*: displayed in place, no prose. Hands forward by *next step*: the tool exists, so it must be used.

**Paragraph 2**

1. **Sentence 1** — *Application transition*: "This can then be applied to the vertices that were defined in the previous section." — the demonstrative "This" links back to matrix S; "can then be applied" announces the next action; the relative clause anchors the inputs. Hands forward by *announcement* (here comes the action).
2. **Sentence 2** — *Result-pointer + cross-reference*: "The new position matrices are shown in equations 3 and 4." — hands the reader to the visual evidence block below and tells them where to look. Hands forward by *display*: the matrices are the outcome.
3. **[Matrices A–H]** — *Worked results*: every vertex × S shown as a completed multiplication. No further sentence; the section ends because the answer is visually complete.

## What This Section Does (content sequence)

1. **State the problem's quantitative demand** — what number/condition the model must produce ("requires… twice the length"). Sets up the need for a specific tool.
2. **Supply the tool with that demand baked in** — show the matrix whose entries are dictated by step 1 ("therefore the scale matrix looks as follows"). Sets up *why* every entry in step 4 is what it is.
3. **Announce the application** — name the objects the tool will act on and locate them in the prior section ("applied to the vertices… defined in the previous section"). Sets up the inputs of step 4.
4. **Cross-reference the result block** — point the reader at numbered equations so they can audit the work ("shown in equations 3 and 4"). Sets up the visual payoff.
5. **Display the full worked output** — every input × tool = output, one per line.

The order matters: the demand must come first because every later matrix entry is a direct mechanical consequence of it; the tool must precede its use; the application sentence must precede the work so the reader knows what each multiplication is doing.

## Paragraph Skeletons (replicable templates)

**SKELETON A — "requirement → tool":**

> "[The problem] requires [object] to be [specific change], therefore the [transformation type] matrix looks as follows: [matrix]."

1. *Slots*: "requires" clause (declarative, past/present) | "therefore" + matrix-name phrase (declarative) | display.
2. *How to fill differently*: slot 1 — name one geometric quantity and one numerical alteration demanded by the brief; slot 2 — name the transformation type (rotation, shear, reflection) that fulfils that alteration; slot 3 — show its matrix.
3. *Original fill*: "The problem requires the cube's edges to be twice the length, therefore the scale matrix looks as follows: [S = diag(2,2,2,1)]."
4. *Demo fill*: "The problem requires the triangle to be reflected across the x-axis, therefore the reflection matrix looks as follows: [M = diag(1,−1,1)]."

**SKELETON B — "tool application → result pointer → displayed work":**

> "This can then be applied to the [inputs] that were defined in the previous section. The new [output] matrices are shown in equations [N] and [N+1]. [input × tool = output, repeated for every input]."

1. *Slots*: demonstrative + "can then be applied" + noun phrase locating prior inputs | new-output noun + "shown in equations" + two equation numbers | block of labelled multiplications.
3. *Original fill*: "This can then be applied to the vertices that were defined in the previous section. The new position matrices are shown in equations 3 and 4. [A–H = S × vertices]."
4. *Demo fill*: "This can then be applied to the triangle's side vectors that were defined in the previous section. The new side vectors are shown in equations 7 and 8. [u′ = M·u, v′ = M·v, w′ = M·w]."

## Express-Idea Vocabulary

- **Cause/consequence**: "therefore" — "therefore the scale matrix looks as follows:" (delivers the tool demanded by the prior sentence).
- **Temporal/procedural sequencing**: "can then be applied" — "This can then be applied to the vertices" (marks the next stage in the procedure).
- **Back-reference / cross-reference**: "defined in the previous section" — "the vertices that were defined in the previous section" (locates inputs in earlier work); "shown in equations 3 and 4" — "The new position matrices are shown" (locates outputs in the visual block).
- **Demonstrative anaphora**: "This" — "This can then be applied" (picks up the matrix just shown without repeating it).

## How to Explain an Idea (replication steps)

This section uses a **requirement → tool → application → worked-output** pattern. To replicate with a new idea:

1. **State the quantitative demand** of the brief in one clause so the reader knows the target number.
2. **Introduce "therefore" and name the tool** (matrix, formula, or operator) that satisfies that demand; display the tool.
3. **Open the next sentence with a demonstrative** ("This", "These") referring to the tool, then add "can then be applied to" plus the objects defined earlier — this guarantees the reader links the tool to the inputs without repetition.
4. **Close the sentence with a cross-reference**: "shown in equations N and N+1" — tells the reader the visual evidence is coming.
5. **Display every worked case** as its own labelled multiplication so each input is auditable separately; do not summarise in prose afterwards.
