## What This Section Does (content sequence)

A References section performs one job in this order:

1. **Citation key** (e.g., "[Bas+08]") — placed first so the reader can cross-reference from in-text markers; encodes author + year (or "+" for et al.).
2. **Author block** — establishes who is responsible; uses "et al." for ≥3 authors, full names otherwise.
3. **Title in quotes** — names the work.
4. **Venue marker "In:"** — a connective that signals the publication container follows (omitted when no container exists, as in Entry 2).
5. **Container + date** — journal/magazine/book/publisher/project, with volume, issue, year, and page range where applicable.
6. **Access tag "url:"** — appended only when the source is online; gives the reader a retrieval point.

The order matters because **identification precedes location** (you can't locate a work before naming it), and **location precedes access** (URL only makes sense after the venue is established). The list as a whole is sorted **alphabetically by lead surname**, so that any citation key can be located by binary search — the section is built for retrieval, not for reading.

## Paragraph Skeletons (replicable templates)

**SKELETON A — Full journal/book citation**
> "[Authors]. "[Title]." In: [Container] [Volume] ([Year]), pp. [range]."

1. *Slots:* slot 1 = lead author surname + initials; slot 2 = quoted title (noun phrase); slot 3 = venue name (proper noun); slot 4 = volume (number); slot 5 = year (parenthesised); slot 6 = page range with "pp.".
2. *How to fill:* slot 1: take the surname of the first listed author. slot 2: copy the article title verbatim, capitalising only the first word. slot 3: write the journal or publisher name in italics-style title case. slot 4: cite the volume number; slot 5: the publication year; slot 6: the inclusive page numbers.
3. *Original:* "Saugata Basu et al. "Polynomials that Sign Represent Parity …". In: Computational Complexity 17 (2008), pp. 377–406."
4. *Demo fill:* "James O'Neill et al. "The Thermodynamics of Black Hole Mergers". In: Physical Review D 102 (2021), pp. 4402–4421."

**SKELETON B — Online article citation**
> "[Authors]. "[Title]." In: [Site name] ([Month Year]). url: [URL]."

1. *Slots:* slot 1 = author or organisation name; slot 2 = quoted title; slot 3 = website/publication name (proper noun); slot 4 = month + year in parentheses; slot 5 = full URL introduced by "url:".
2. *How to fill:* slot 1: name the author or, if absent, the publishing organisation. slot 2: copy the headline verbatim. slot 3: write the hosting site. slot 4: locate the publication month/year from the page footer. slot 5: paste the canonical URL; do not shorten.
3. *Original:* "Erica Klarreich. "Simple Set Game Proof Stuns Mathematicians". In: Quanta Magazine (May 2016)."
4. *Demo fill:* "Priya Anand. "How Coral Reefs Remember Heatwaves". In: The Atlantic (Aug. 2023). url: https://www.theatlantic.com/science/…"

**SKELETON C — Institutional/unpublished report**
> "[Author]. "[Title]." [Institution], [Month Year]."

1. *Slots:* slot 1 = author (single name); slot 2 = quoted title; slot 3 = host institution; slot 4 = date.
2. *How to fill:* slot 1: name the sole author. slot 2: state the report title. slot 3: name the university or centre. slot 4: state the month and year the report was issued.
3. *Original:* "Corey Dunn. "A proof that Corey finally understands". California State University, Feb. 2008."
4. *Demo fill:* "Min-Jae Park. "Closed-Form Solutions for Cubic Diophantine Triples". Seoul National University, Nov. 2022."

## Express-Idea Vocabulary

This section uses **no prose connectives** (no "therefore", "however", "firstly") because it is not prose. Instead it uses **field-tag connectives** — labels that bridge data slots:

- **Venue tag:** "In: Computational Complexity 17" — introduces the container that holds the cited work.
- **Volume/issue/year cluster:** "(2008), pp. 377–406" — anchors the work temporally and spatially in the container.
- **Multi-author shorthand:** "Saugata Basu et al." — collapses unnamed co-authors into one tag.
- **Access tag:** "url: http : / / www . math . ubc . ca / …" — adds a retrieval pointer after the standard fields.
- **Section locator:** "In: Section 7.6.1." — used when the cited material is a subsection of a larger platform (Entry 9).
- **Date precision variant:** "(May 2016)" vs. "(2008)" — month added when the year alone would not let the reader find the piece (web articles); omitted for bound volumes where issue/discriminator is enough.

These tags do the work that connectives do in prose: they tell the reader **what kind of information is coming next**.

## How to Explain an Idea (replication steps)

This section does not deploy an explanation pattern (no definition→unpack→example, no cause chain, no worked calculation). It deploys an **identification pattern**: *attribute → label → locate → date → point-of-access*. To reproduce it for a new piece of research:

1. **Mint a citation key** (author + year, or author + "+" if 3+ authors).
2. **Write the author block** in plain text, inverting surname-first for the lead author and using "et al." once three or more are listed.
3. **Wrap the work's title in double quotes**, preserving the original wording.
4. **Decide whether a container exists**: if the work sits inside a journal, book, or website, insert the connective "In:" followed by the container's name, volume, issue, year, and page range; if not (e.g., a stand-alone report), drop "In:" and write the host institution directly.
5. **Append a date**; add a month only for web sources where the year alone is insufficient.
6. **Append "url:"** if and only if the source is online and not already pinned to a DOI; never shorten the link.
7. **Sort the finished list alphabetically by lead surname** so any in-text marker can be located by eye.

The section's "logic" is therefore the logic of **a database record**, not of an argument: each entry is complete in itself, and the order is mechanical.
