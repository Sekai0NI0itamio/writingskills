## What This Section Does (content sequence)

This is a **data presentation + method-rationale** block. The ordered sequence is:

1. **Raw data table first** — places every observation (country × year) in front of the reader so the reader can see what is being processed.
2. **Justification sentence** — explains *why* the raw numbers in the table cannot be compared directly (cases are population-relative, so country size distorts the figures).
3. **Standardisation procedure sentence** — names the specific mathematical transformation applied (incidence per 100,000 people, per year).
4. **Implied next move (text cuts off here):** walk through the table year-by-year, showing the standardized values have been computed — the procedure sentence is the bridge into evidence.

**Why this order:** The table must come first because the justification sentence refers to "the data" — the reader must have seen the data to feel why standardisation matters. Justification must precede procedure because a method only feels necessary once the flaw in the raw data has been named. Procedure must come immediately before the year-by-year walkthrough because the walkthrough is the *evidence* that the procedure was actually carried out. Generalised rule: **show the raw → name the flaw → name the fix → apply the fix visibly.** Reversing any pair breaks the logical pull.

## Express-Idea Vocabulary

- **Causal / reason connectors:** "As the cases of malaria are relative to the population of the country" — opens the justification clause linking observation to consequence.
- **Anaphoric reference (answering the prior sentence):** "This was done by calculating the incidence" — picks up "had to be standardized" and supplies the mechanism.
- **Specification / scope-of-operation phrases:** "per 100,000 people" and "for each year" — narrow the general action down to a concrete denominator and a concrete repeating unit.
- **Transformation verbs (past passive):** "had to be standardized" — places the corrective action in completed, justified tense.
- **Definition-by-formula phrases:** "calculating the incidence of … per …" — defines the method operationally rather than abstractly.

## How to Explain an Idea (replication steps)

The pattern is: **name-the-dependency → name-the-fix → define-the-fix-operationally.**

1. **Identify the hidden variable** that distorts your raw numbers (e.g. population, area, baseline ability, time exposed). State it in a clause introduced by "As" or "Since".
2. **State that the raw data cannot be used directly** because of that variable. Use the construction "the data had to be [verb]ed" in past passive to mark it as a completed, necessary step.
3. **Define the transformation operationally** — give a named quantity (rate, index, z-score, ratio) and the exact denominator used.
4. **State the unit of repetition** with "for each [unit]" so the reader knows the operation is applied row-by-row or column-by-column.
5. **Hand the reader into the table** by letting the final phrase of the paragraph ("for each year", "for each school") echo the column/row structure of the data block that follows.

Following these five steps forces the reader to feel the problem before seeing the solution, and the solution is always phrased in a form that points directly at the evidence the table is about to supply.
