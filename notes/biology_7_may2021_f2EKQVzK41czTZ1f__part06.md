## What This Section Does (content sequence)

This section performs a **descriptive-statistics display** for a multi-treatment experiment. The ordered sequence is:

1. **First: state what the table shows and its units** — sets up which variable and which measurement scale the reader is about to see.
2. **Second: list every treatment as a column header, ending with a pooled "general population" column** — establishes the comparison set so each subsequent row is read as a treatment-vs-treatment comparison; placing "general population" last acts as a reference baseline.
3. **Third: rows in this order — mean, then standard deviation, then sample variance, then count** — moves from the most intuitive summary (mean) to increasingly technical spread measures (SD, then variance), with count last as a credibility check on the comparisons above.
4. **Fourth: repeat the entire block for a second dependent variable** — by mirroring table structure exactly, the reader compares the *same* treatments on a *different* outcome without re-learning the layout.
5. **Fifth: provide one figure per dependent variable that graphs the mean only** — strips the table down to its single most reader-friendly comparison.

**Why this order:** each unit sets up the contract the next one fulfils. Title promises variables → columns deliver the groups → statistic rows deliver the summaries in difficulty order → second table redeploys the same contract on a new variable → figure condenses the mean row into a visual for quick scanning.

**Generalised replication:** for any experiment with k treatments and one or more response variables, present (a) a titled table per response variable, (c) with all treatments as columns plus a pooled/reference column, (b) rows ordered mean → SD → variance → n, and (c) close with one mean-only figure per response variable.

### SKELETON A — Descriptive-statistics table block
**Slot template:**
> "[Table number]. Showcasing the [statistic list] of the [variable] ([unit]) measured"
> Column headers: [treatment 1] | [treatment 2] | … | [general/reference population]
> Row 1 header: mean ([unit] ± [uncertainty])
> Row 2 header: Standard Deviation
> Row 3 header: Sample Variance
> Row 4 header: count

1. **What each slot holds:**
   - Title slot: ordinal table number + verb "Showcasing" + comma-separated statistic names + "of the" + variable name + parenthesised unit + past participle "measured".
   - Column slot: each treatment expressed as a noun phrase, optionally with its concentration/condition attached (e.g., "microalgae 0.5%"), final column a pooled baseline.
   - Row header slot: statistic name (noun phrase), with mean carrying parenthesised unit and explicit uncertainty.
   - Final row: integer sample size labelled "count".

2. **How to fill with a DIFFERENT idea:** Pick any experiment with ≥3 treatment groups and ≥1 quantitative response. Title slot: name your response variable and its unit in parentheses. Column slot: list your groups left-to-right in increasing "intensity" and finish with a pooled or control reference column. Row slot: keep mean first (with unit and measurement uncertainty), then SD, then variance, then count. Do NOT change row order.

## Express-Idea Vocabulary

This section expresses ideas through **layout verbs, statistic labels, and parallelism**, not connectives. Grouped by job:

- **Sequencing / labelling:** ordinal numerals — "Table 4", "Table 5", "Fig.3", "Fig.4" (used to mark order across presentation units so the reader knows which comes first).
- **Action / framing verb — single verb doing the job of "this section presents":** "Showcasing the mean, standard deviation, sample variance" — used twice to announce what each table contains.
- **Specification (parenthetical units and uncertainty):** "of the height (cm) measured", "fresh weight (gr.) measured", "mean (cm ± 0.05 cm)", "mean (gr ± 0.1 gr)" — each attaches a unit and (for the mean) an explicit measurement uncertainty to anchor the reader's scale.
- **Comparison handle — pooled/baseline label:** "general population" (used as the final column in both tables to act as the comparison anchor for every treatment column to its left).
- **Definition / categorisation of statistics:** "mean", "Standard Deviation", "Sample Variance", "count" — the row labels themselves do the work of defining which summary is being shown.
- **Visual-summary cue:** "Fig.[n] mean [variable] of treatments" — uses the single word "mean" to specify *which* row of the table the figure condenses, and "of treatments" to specify that every group is plotted.

Connectives such as "therefore", "however", "in particular" are absent because the *tabular layout itself* carries the logic (same row = same statistic; same column = same group).

## How to Explain an Idea (replication steps)

The pattern this section relies on is **"announce → tabulate in a fixed statistic ladder → mirror for a second variable → visualise the simplest row."** It is a *layered descriptive display*, not a sentence-level explanation.

Step-by-step to replicate with a new idea:

1. **Announce** what is being displayed in a single title line that names the response variable, its unit, and the list of summary statistics, using the verb "Showcasing" so the reader knows the table is descriptive, not inferential. ("Showcasing the mean, standard deviation, sample variance of the [variable] ([unit]) measured".)
2. **Lay out columns** as every treatment/condition left-to-right, finishing with a pooled or reference column so every other column can be read against a baseline. Keep the column order identical across every table you produce.
3. **Lay out rows** in a fixed statistic ladder: mean (with unit and explicit uncertainty first) → Standard Deviation → Sample Variance → count. Do not reorder rows between tables.
4. **Mirror the entire table** for each additional response variable, changing only the title, the unit, and the numbers; this lets the reader compare the same treatments across variables without re-learning the layout.
5. **Provide one figure per response variable**, captioned "Fig.[n] mean [variable] of treatments", so the reader has a quick visual of the most intuitive statistic (the mean) without needing to parse SD or variance numbers.
6. **Maintain parity of "count"** (equal n per column) so the reader is implicitly licensed to compare columns directly; if n differs, the table loses its hand-off logic.
